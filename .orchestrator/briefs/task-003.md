# task-003 — Build the executor layer: pure InstallPlan→Step compiler plus a dry-run-capable runner (pacstrap, chroot file writes, init-specific service enabling)

- **Capability:** 1. Installer shell — friendly, composable
- **Complexity:** standard
- **Rationale:** Catalog (data) and plan resolver (brain) are done and fully tested; the InstallPlan currently cannot touch a disk. The next layer down in ADR-3's strict stack is the executor. Building it as a pure step compiler + thin runner keeps the whole thing unit-testable without root or a live ISO, and encodes the genuinely tricky domain knowledge — dinit vs runit service enabling on Artix, pacstrap/chroot ordering — in tested pure code. After this, the TUI is the only missing layer.
- **Depth note:** Adds zero new user-facing scope; it deepens the existing install pipeline so the already-built plan logic becomes actually executable end-to-end. The dry-run mode also becomes the TUI's confirmation screen for free.

## Files
- `packages/wheatley-installer/wheatley_installer/executor.py`
- `packages/wheatley-installer/tests/test_executor.py`

## Contracts
READ packages/wheatley-installer/wheatley_installer/plan.py and catalog.py FIRST and import from them — do not redefine their types. Consume: InstallPlan{packages: List[str], services: List[str], files: List[PlannedFile], warnings: List[str]}, PlannedFile{path, content, mode}. Provide in executor.py: (1) Step dataclasses — RunCommand{argv: List[str], description: str}, WriteTargetFile{path: str (absolute path INSIDE target, e.g. '/etc/skel/.bashrc'), content: str, mode: int, description: str} — plus an ExecutorError(Exception); (2) pure function compile_steps(plan: InstallPlan, *, target: str = '/mnt', init_id: str) -> List[Step] with NO side effects and no imports of subprocess at call time; (3) execute(steps: List[Step], *, dry_run: bool = False, log: Callable[[str], None] = print) -> None which for dry_run=True only logs one deterministic line per step ('DRY-RUN: <description>') and performs zero subprocess calls and zero filesystem writes, and for dry_run=False runs RunCommand via subprocess.run(check-style) and writes WriteTargetFile under target with the given mode (creating parent dirs), raising ExecutorError on the first failure with the failing step's description in the message. Python 3 stdlib only. Each file under 500 lines. Keep unittest style consistent with the existing tests/ directory.

## Brief
Create packages/wheatley-installer/wheatley_installer/executor.py implementing ADR-4 (pure compiler + thin runner) and packages/wheatley-installer/tests/test_executor.py.

COMPILER (compile_steps): given an InstallPlan, a target mountpoint (default /mnt), and the chosen init_id, emit a deterministic ordered List[Step]:
1. One RunCommand for package installation of ALL plan.packages in a single call. This distro is Artix-based built with artools, so use basestrap (Artix's pacstrap): argv = ['basestrap', target] + plan.packages. Do not split into multiple installs.
2. fstab generation: RunCommand ['fstabgen', '-U', target] with a description noting output must be redirected to <target>/etc/fstab — model this as argv ['sh', '-c', 'fstabgen -U <target> >> <target>/etc/fstab'] so it is actually runnable.
3. One WriteTargetFile per plan.files entry, in plan.files order (already sorted by path), preserving content and mode verbatim.
4. Service enabling, one step per plan.services entry in order, dependent on init_id: for init_id 'dinit' emit RunCommand ['artix-chroot', target, 'dinitctl', 'enable', <service>] — BUT because dinitctl needs a running daemon, prefer the offline form: RunCommand ['artix-chroot', target, 'ln', '-sf', '/etc/dinit.d/<service>', '/etc/dinit.d/boot.d/<service>'] (use this symlink form; it works in a chroot with no daemon). For init_id 'runit' emit RunCommand ['artix-chroot', target, 'ln', '-sf', '/etc/runit/sv/<service>', '/etc/runit/runsvdir/default/<service>']. For any other init_id raise ExecutorError naming the unsupported init. Verify the exact init ids ('dinit', 'runit') against catalog/catalog.json and use whatever ids appear there.
5. Every Step must carry a human-readable description (used verbatim by dry-run and by the future TUI confirmation screen), e.g. 'Install 47 packages with basestrap', 'Write /etc/skel/.bashrc', 'Enable service bluetoothd (dinit)'.
compile_steps must be pure: same inputs → identical output list (write an equality-based test), no filesystem, subprocess, or clock access.

RUNNER (execute): iterate steps in order. dry_run=True: call log('DRY-RUN: ' + description) per step, nothing else — assert in tests via a temp dir that no files appear and by monkeypatching subprocess.run to a function that raises if called. dry_run=False: RunCommand → subprocess.run(argv), raise ExecutorError (chaining the cause, message contains the step description) on nonzero return; WriteTargetFile → join target-relative path safely under the target dir (reject any path not starting with '/' or containing '..' with ExecutorError), create parent dirs, write content, os.chmod to mode. In tests, exercise real execution ONLY with harmless commands (e.g. ['true'], ['false']) and WriteTargetFile into a tempfile.TemporaryDirectory used as target — never touch the real system.

TESTS (>= 20 new, unittest, style-matched to existing tests): golden ordering test (basestrap first, then fstab, then files in order, then services); determinism test (two compiles compare equal); dinit vs runit symlink argv tests using ids from catalog.json; unsupported init raises; empty-services and empty-files plans compile without those step groups; dry-run writes nothing and spawns nothing; real-run WriteTargetFile creates file with exact content and mode in a temp target and creates parents; failing RunCommand (['false']) raises ExecutorError containing the description; path traversal ('../x', relative path) rejected; an integration test that builds a real plan via load_catalog(catalog/catalog.json) + resolve_plan with dinit + a session + bluetooth, compiles it, and asserts the bluetooth service-enable step and the /etc/skel/.bashrc write step are present.

Run the FULL suite (python -m unittest discover from packages/wheatley-installer or however existing tests are invoked — check how tests/test_plan.py is structured) and ensure all old + new tests pass. Create no files beyond the two listed. Do not modify plan.py or catalog.py.

## Acceptance criteria
1. Full test suite passes without root: all 74 existing tests plus >= 20 new executor tests, runnable via python -m unittest discover (or the repo's established invocation) from packages/wheatley-installer.
2. compile_steps is provably pure and deterministic: a test compiles the same InstallPlan twice and asserts the two step lists compare equal, and executor.py performs no subprocess/filesystem access at import or compile time.
3. Init-specific service enabling is tested for BOTH inits present in catalog.json: dinit produces artix-chroot ln -sf /etc/dinit.d/<svc> /etc/dinit.d/boot.d/<svc> steps, runit produces /etc/runit/sv → /etc/runit/runsvdir/default symlink steps, and an unsupported init_id raises ExecutorError.
4. execute(steps, dry_run=True) is verified side-effect-free by tests (no subprocess spawned — patched subprocess.run raises if invoked; temp target dir remains empty), while dry_run=False in a temp target writes PlannedFile content with the exact mode and raises ExecutorError with the step description on a failing command (['false']).
5. Both new files are under 500 lines, import only the Python stdlib plus wheatley_installer.plan/catalog, and no other repo files are modified.
