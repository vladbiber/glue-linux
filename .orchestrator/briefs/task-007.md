# task-007 — Add disk-selection and identity text-entry screens to the wizard: pure form-field state machine (ui_forms.py) integrated into ui_model flow, rendered with masked password support, wired end-to-end in __main__

- **Capability:** 9. Disk, boot & identity (required for 'installs & boots')
- **Complexity:** complex
- **Rationale:** Cycles 6–7 built the disk and identity layers as pure step compilers, but both are reachable ONLY via CLI flags (--disk, identity flags) — the actual wizard never asks for a target disk, hostname, username, password, locale, or timezone. The old whiptail installer collected all of these interactively; until the TUI does too, the 'friendly installer' cannot perform a real install without memorizing flags. This is the last functional gap before packaging (capability 10), and it purely deepens existing layers: ui_model gains screens, render/tui gain text input, __main__ swaps flag-plumbing for wizard output.
- **Depth note:** Zero new capabilities: every screen added maps 1:1 onto data structures that already exist and are already tested (disks.DiskInfo from parse_lsblk, identity.IdentitySpec). This completes the existing disk/identity work end-to-end through the existing TUI, following the established pure-model/thin-view split (ADR-3/5/8).

## Contracts
MUST NOT break existing public APIs: ui_model.Wizard still produces a plan.Selection; identity.IdentitySpec and disks module signatures unchanged. New pure module ui_forms.py: a FormField dataclass (key, label, value, secret: bool, validator) and typed events (feed_char(c), backspace(), submit()) with validation errors surfaced as strings — NO curses/subprocess/os imports (assert in tests). ui_model integrates: (a) a disk-pick screen built from a provided List[DiskInfo] (injected as a value — ui_model must NOT call disks.discover() itself; __main__ calls discover(), or synthesizes a fake disk in --dry-run exactly like the current fallback), shown as single-select with device name + size + model; (b) identity form screens for hostname, username, password (+confirm), locale, timezone — locale/timezone may be choice screens if the catalog carries options, else text entry with sensible defaults ('en_US.UTF-8', 'UTC') prefilled. Password screens are secret=True: ui_model stores the real value; render.py displays '*' per char and MUST NEVER emit the plaintext (test asserts plaintext not in any rendered line). Wizard output extends to carry (selection, device_path, IdentitySpec) — a small dataclass WizardResult is acceptable. Validators: hostname RFC-1123-ish ([a-z0-9-], no leading/trailing '-', 1-63 chars), username POSIX ([a-z_][a-z0-9_-]{0,31}), password non-empty + confirm matches, reject mismatch with a re-entry path. tui.py passes printable chars/KEY_BACKSPACE to the wizard on form screens; all curses-specific code stays in tui.py. __main__ keeps --disk and identity flags working as OVERRIDES (skip the corresponding screens when provided) so existing dry-run invocations still pass. All files ≤500 lines (split test files if needed). Tests: python -m unittest discover -s tests from packages/wheatley-installer/, no root/TTY.

## Brief
Repo: ~/wheatley-linux. Work in packages/wheatley-installer/ (Python 3 stdlib only, strict pure-logic/thin-IO layering — read ui_model.py, render.py, tui.py, __main__.py, disks.py, identity.py, and existing tests first to match conventions).

GOAL: the interactive wizard currently ends at a summary but never asks WHERE to install or WHO the user is — disk and identity come only from CLI flags in __main__.py. Add wizard screens so a user running `python -m wheatley_installer --dry-run` with no other flags is walked through: existing screens → disk selection → hostname → username → password + confirm → locale → timezone → summary (summary now shows disk + identity, password masked).

BUILD:
1. `ui_forms.py` (new, pure): FormField dataclass {key, label, value:str, secret:bool, error:Optional[str]} plus validators (hostname: 1-63 chars of [a-z0-9-], no leading/trailing hyphen; username: ^[a-z_][a-z0-9_-]{0,31}$; nonempty for password). Event functions or a small FormScreen class: feed_char (printable only), backspace, submit→(ok, error). No curses/os/subprocess imports.
2. Extend `ui_model.py` Wizard: new screen kinds DISK_SELECT (single-select over injected List[disks.DiskInfo]; label like '/dev/sda  20 GiB  QEMU HARDDISK') and FORM (wraps a FormField). Insert after existing flow, before summary: disk → hostname → username → password → password-confirm (mismatch sets error and returns to password entry with both cleared) → locale (default 'en_US.UTF-8') → timezone (default 'UTC'). Wizard is constructed with the disk list as a plain value. Final output: a WizardResult dataclass carrying the existing Selection, the chosen device path, and an identity.IdentitySpec. Keep ui_model.py ≤500 lines — move form logic into ui_forms.py.
3. `render.py`: render FORM screens (label, current value — '*' * len(value) when secret, error line if set) and DISK_SELECT like existing single-selects. Never render plaintext of secret fields anywhere including the summary.
4. `tui.py`: on FORM screens forward printable characters and backspace (curses.KEY_BACKSPACE, 127, 8) to the wizard; Enter submits. Everything else unchanged.
5. `__main__.py`: build the disk list via disks.discover() (real run) or the existing synthetic dry-run fallback; pass into Wizard. If --disk or identity flags are given, pre-fill/skip those screens (flags remain overrides so current invocations work unchanged). Feed WizardResult into the existing plan→steps pipeline (disk_steps + identity_steps + compile_steps) exactly as the flag path does today.
6. Tests: new tests/test_ui_forms.py (validators incl. negative cases: empty hostname, 64-char hostname, 'Foo!' username, leading '-', password mismatch flow) and extend test_ui_model.py (full walk-through producing a WizardResult with expected IdentitySpec; disk screen lists injected disks; skipping behavior with prefilled values) and test_render.py (secret field renders as asterisks; assert the literal password string appears in NO rendered line). Preserve all 295 existing tests.

Run `python -m unittest discover -s tests` from packages/wheatley-installer/ and ensure everything passes. Then verify `python -m wheatley_installer --dry-run --help` still works and document the new flow briefly in the module docstring of ui_model.py.
