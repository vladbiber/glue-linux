# task-006 — Build the identity layer: pure IdentitySpec + identity_steps (hostname, locale, timezone, user + password via chpasswd stdin) with RunCommand stdin support, wired into __main__

- **Capability:** 9. Disk, boot & identity (required for 'installs & boots')
- **Complexity:** standard
- **Rationale:** Cycle 6 delivered the disk+bootloader layer (disks.py, 236 tests, --disk wiring) — verified in the repo. The installed system now boots but is unusable and insecure: no hostname, no user, no password, no locale, no timezone — root with no credentials. The old whiptail script configured all of these; the new installer configures none. This is the last missing piece of 'a system that actually boots and you can log into', and it must exist as pure step-compilation before any wizard screen can collect the values, so it is the unambiguous depth-first next step.
- **Depth note:** Deepens the existing executor/disks pattern (pure spec → steps, thin wiring in __main__) rather than adding any new surface. Follows ADR-6 exactly: identity.py mirrors disks.py. The one shared-contract change (RunCommand.stdin) hardens the whole step model — secrets never leak into argv/ps.

## Contracts
READ FIRST: wheatley_installer/executor.py (Step = RunCommand | WriteTargetFile, compile_steps, execute), wheatley_installer/disks.py (the pattern to mirror: pure dataclasses + pure *_steps() returning List[Step] + thin subprocess wrapper), wheatley_installer/__main__.py (wiring, dry-run behavior, _fail/EXIT codes). MUST NOT change: existing public signatures compile_steps(plan, *, target, init_id), execute(steps, dry_run, log), disk_steps/bootloader_steps, load_catalog, resolve_plan. MAY extend: RunCommand gains an optional field `stdin: Optional[str] = None` (default None so every existing construction site and test stays valid); execute() passes it to subprocess via input=/text mode; dry-run logging MUST NOT print stdin contents (log e.g. '<stdin: 14 bytes>' or nothing). New module wheatley_installer/identity.py: frozen dataclass IdentitySpec(hostname: str, username: str, password: str, locale: str = 'en_US.UTF-8', timezone: str = 'UTC') with a validate() or __post_init__ raising IdentityError (hostname: RFC-952-ish [a-z0-9][a-z0-9-]{0,62}, no leading/trailing '-'; username: ^[a-z_][a-z0-9_-]{0,31}$; password non-empty; locale must look like ll_CC.UTF-8; timezone must match Area/City form ^[A-Za-z_+-]+(/[A-Za-z_+-]+){1,2}$). Pure function identity_steps(spec, *, target='/mnt') -> List[Step]. Python 3 stdlib only. All files ≤500 lines. Tests use unittest (pytest is NOT installed): run with `python -m unittest discover -s tests` from packages/wheatley-installer/.

## Brief
Work in /home/gentoobdw/wheatley-linux/packages/wheatley-installer/. The installer stack is: catalog.py → plan.py (Selection→InstallPlan) → executor.py (InstallPlan→List[Step], Step = RunCommand | WriteTargetFile, execute() runs them with dry_run support) → disks.py (pure disk/bootloader steps) → __main__.py (the only wiring point; has --dry-run/--target/--disk flags and runs the curses wizard or headless dry-run). Read executor.py, disks.py and __main__.py before writing anything.

1) executor.py: add optional `stdin: Optional[str] = None` to the RunCommand dataclass (keyword-only, default None, so all existing call sites are untouched). In execute(), when a RunCommand has stdin, pass it to the subprocess call as text input. The dry-run/log path must NEVER echo stdin contents — render at most a redacted marker like '<stdin: N bytes>'.

2) New file wheatley_installer/identity.py, mirroring disks.py style (module docstring, frozen dataclasses, IdentityError(Exception)): IdentitySpec(hostname, username, password, locale='en_US.UTF-8', timezone='UTC') with strict validation per the contracts. identity_steps(spec, *, target='/mnt') -> List[Step] producing, in order: (a) WriteTargetFile /etc/hostname with hostname + trailing newline; (b) WriteTargetFile /etc/hosts with the standard 127.0.0.1 localhost / ::1 localhost / 127.0.1.1 <hostname> block; (c) RunCommand arch-chroot <target> ln -sf /usr/share/zoneinfo/<timezone> /etc/localtime; (d) RunCommand arch-chroot <target> hwclock --systohc; (e) WriteTargetFile /etc/locale.gen containing '<locale> UTF-8\n' then RunCommand arch-chroot <target> locale-gen, then WriteTargetFile /etc/locale.conf with 'LANG=<locale>\n'; (f) RunCommand arch-chroot <target> useradd -m -G wheel -s /bin/bash <username>; (g) set the user password AND the root password via RunCommand(['arch-chroot', <target>, 'chpasswd'], stdin='<name>:<password>\n') — one chpasswd call for the user and one for root (root gets the same password, matching the old whiptail behavior); the password must appear ONLY in the stdin field, never in argv; (h) WriteTargetFile /etc/sudoers.d/10-wheel with '%wheel ALL=(ALL:ALL) ALL\n' and mode 0o440 if WriteTargetFile supports a mode field — read the dataclass first; if it has no mode field, instead emit RunCommand arch-chroot chmod 440 after the write.

3) __main__.py wiring: add CLI flags --hostname (default 'wheatley'), --username, --password, --locale, --timezone. If --username is provided, build IdentitySpec (catching IdentityError → _fail with the existing invalid-usage exit code) and append identity_steps(...) to the executed steps AFTER the main compile_steps/system steps and BEFORE any final unmount/finish steps if such exist — read the current step-assembly order in __main__.py and slot identity in where the old whiptail flow did (after pacstrap/config, before reboot). Headless dry-run (`python -m wheatley_installer --dry-run --disk /dev/fake --username test --password secret ...` with whatever non-interactive mechanism test_main_headless.py already uses) must show the identity steps with the password redacted.

4) Tests: new tests/test_identity.py with ≥20 tests covering: valid spec round-trip; hostname/username/locale/timezone/password validation rejections (≥8 negative cases); exact step ordering; hostname file content; hosts file contains 127.0.1.1 line; chpasswd steps carry password only in stdin (assert password string does NOT appear in any argv of any step); sudoers content; target path honored. Extend tests/test_main_headless.py (or add cases) proving: identity flags produce identity steps in dry-run output and the literal password never appears in captured output. Update executor runner tests only if needed for the stdin field (e.g. a test that execute() passes stdin through — mock subprocess). ALL existing 236 tests must still pass: run `python -m unittest discover -s tests` and report the final count.

## Acceptance criteria
1. `python -m unittest discover -s tests` from packages/wheatley-installer/ exits 0 with ≥260 tests, including ≥20 new tests in tests/test_identity.py of which ≥8 are negative validation cases
2. grep of the compiled steps in tests asserts the password appears in NO RunCommand argv — only in RunCommand.stdin — and a headless dry-run with --username/--password never prints the literal password to stdout/stderr
3. identity_steps() output contains, in order: /etc/hostname write, /etc/hosts write, zoneinfo symlink, hwclock, locale.gen write + locale-gen + locale.conf, useradd -m -G wheel, two chpasswd RunCommands (user and root) with stdin set, and a wheel sudoers drop-in — verified by an explicit ordering test
4. RunCommand keeps backward compatibility: all pre-existing tests pass unmodified except where the stdin feature is explicitly under test; identity.py has no subprocess/curses imports and every touched file stays ≤500 lines
