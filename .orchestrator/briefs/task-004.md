# task-004 — Build the curses view layer and `python -m wheatley_installer` entry point: pure line renderer (render.py) + thin curses driver (tui.py) + wired dry-run-capable main

- **Capability:** 1. Installer shell — friendly, composable
- **Complexity:** complex
- **Rationale:** Every logic layer is done and tested (catalog → plan → executor → ui_model wizard brain, 154 tests). The single missing piece between this stack and a usable installer is the view: something must paint Screens, translate keystrokes into Wizard events, and wire Selection → resolve_plan → compile_steps → execute. Nothing else on the roadmap can be meaningfully verified end-to-end until the program is actually runnable, so this is the unambiguous depth-first next step — it completes capability 1 rather than starting anything new.
- **Depth note:** Adds zero new features or data; it is purely the presentation + wiring of already-tested logic. The renderer/driver split keeps the new code testable to the same standard as the rest of the stack (only ~100 lines of the whole installer will be untestable curses glue).

## Contracts
READ ui_model.py, plan.py, executor.py, catalog.py FIRST and consume them unchanged — do not modify any existing module or test. ui_model API: Wizard(catalog); wizard.current_screen() -> Screen{key,title,kind:'info'|'radio'|'multi'|'toggle'|'summary',items:List[Item],notice:Optional[str]}; Item{id,label,description,ease:Optional[int],lightness:Optional[int],keybinds:Optional[str],screenshot:Optional[str],recommended:bool,selected:bool,section:Optional[str]}; events wizard.apply(Toggle(item_id)|Choose(item_id)|SetFlag(value)); wizard.next()/wizard.back() (next() raises ValidationError with a user-readable message); wizard.is_finished(); wizard.to_selection(). Then: plan.resolve_plan(catalog, selection) -> InstallPlan (raises PlanError); executor.compile_steps(plan, target='/mnt', init_id=selection.init_id) -> List[Step]; executor.execute(steps, dry_run=..., log=...). catalog.load_catalog(Path) raises CatalogError. NEW contract to implement in render.py (pure, stdlib-only, MUST NOT import curses): StyledLine = Tuple[str, str] where style is one of 'title'|'notice'|'item'|'item_selected'|'item_cursor'|'detail'|'recommended'|'section'|'error'|'footer'; render_screen(screen: Screen, cursor: int, width: int, height: int, error: Optional[str] = None) -> List[StyledLine]. tui.py maps style tags to curses color pairs from the amber palette (#100A02 bg, #A66900 dim, #F1B00A bright; init_color/init_pair when can_change_color(), graceful fallback to COLOR_YELLOW otherwise).

## Brief
Goal: make the installer runnable end-to-end. 1) render.py (pure): implement render_screen as specified in contracts. It must render: the screen title; the notice verbatim when present (word-wrapped to width — this is how the 'multiple sessions, pick at login' message and the dinit guidance reach the user); each Item as a cursor row ('> ' marker at cursor index), with '[x]/[ ]' for kind='multi', '(o)/( )' for kind='radio'/'toggle'; a ' (recommended)' suffix styled 'recommended' when item.recommended; section headers (style 'section') whenever item.section changes between consecutive items (this separates the "Desktop environments (optional)" DE-slop group); a detail block for the item under the cursor showing description, 'Ease: N/5', 'Lightness: N/5', 'Keys: <keybinds>', and 'Preview: <screenshot path>' when those fields are non-None; the error argument (style 'error') when set; a footer line with key hints (↑/↓ move, Space toggle/choose, Enter next, B back, Q quit). All output must fit width (truncate with '…') and the item list must scroll so the cursor row is always visible within height. Pure function: same inputs → same output, no I/O, no curses import. 2) tui.py: thin curses driver run_tui(catalog) -> Optional[Selection]. Key loop: arrows/jk move cursor, Space applies Toggle/Choose (for kind='toggle' screens use SetFlag or Toggle exactly as ui_model.apply expects — read its apply() to get this right), Enter calls wizard.next() catching ValidationError into the error line (cleared on next keypress), B/left calls wizard.back(), Q asks 'Quit installer? [y/N]' and returns None. When wizard.is_finished(), return wizard.to_selection(). No business logic: tui.py must contain no references to catalog item ids, package names, or init names. 3) __main__.py: argparse with --catalog PATH (default: the shipped catalog/catalog.json resolved relative to the package), --target PATH (default /mnt), --dry-run, and --validate-catalog (headless: load + validate catalog, print counts of kernels/inits/sessions/shells, exit 0; exit 2 with the CatalogError message on invalid). Normal flow: load catalog → run_tui → if None print 'Cancelled.' exit 1 → resolve_plan → compile_steps → print a plan summary (package count, service count, files) and with --dry-run pass dry_run=True to execute so steps are printed, not run; without --dry-run require an explicit typed 'yes' confirmation on stdin before execute(dry_run=False). Wrap PlanError/CatalogError/ExecutorError into clean stderr messages + nonzero exit, never tracebacks. 4) tests/test_render.py (≥15 tests): cursor marker position, checkbox vs radio glyphs, recommended suffix present for dinit item, notice wrapped and present on the sessions screen (assert the multi-select login text appears), section header emitted for DE section, detail block shows ease/lightness/keybinds/screenshot for a real catalog session, scrolling keeps cursor visible for small height, truncation at narrow width, determinism (two calls equal), no curses import (assert 'curses' not in sys.modules after importing render). 5) tests/test_main_headless.py (≥4 tests): run `python -m wheatley_installer --validate-catalog` via subprocess against the real catalog (exit 0, counts in stdout) and against a broken temp catalog (exit 2); --help exits 0; module import of __main__ must not require a TTY. Use the real shipped catalog.json in tests wherever possible. Keep every file ≤500 lines; stdlib only.

## Acceptance criteria
1. All pre-existing 154 tests still pass unmodified, plus ≥15 new tests in tests/test_render.py and ≥4 in tests/test_main_headless.py, all passing headlessly (no TTY, no root) via `python -m pytest packages/wheatley-installer/tests/` or unittest discover.
2. render.py imports neither curses nor any wheatley_installer module beyond ui_model dataclasses, and a test proves importing it does not load curses; tui.py is the only file importing curses; grep confirms tui.py contains no catalog item ids or package names (no 'dinit', 'cachyos', 'plasma', 'steam' literals).
3. `python -m wheatley_installer --validate-catalog` (run from packages/wheatley-installer/) exits 0 and prints kernel/init/session/shell counts matching the shipped catalog.json; an intentionally broken catalog makes it exit 2 with the CatalogError message and no traceback.
4. A rendered sessions screen (unit test, real catalog) contains the multi-select login notice text, the '(recommended)' marker appears on the dinit row of the init screen, and the DE section header separates plasma/xfce from the WM items.
5. All new files are ≤500 lines and stdlib-only; existing modules (catalog.py, plan.py, executor.py, ui_model.py) have zero diffs.
