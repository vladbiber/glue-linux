# task-005 — Build the disk & bootloader layer: pure lsblk parsing, UEFI/BIOS partition planning, and compile_steps integration (sgdisk/mkfs/mount → pacstrap → grub) with dry-run support

- **Capability:** 9. Disk, boot & identity (required for 'installs & boots')
- **Complexity:** complex
- **Rationale:** Capability 1 is complete: the installer runs end-to-end in dry-run (186 tests). But it cannot actually install a bootable system — it assumes /mnt is already partitioned/mounted and never installs a bootloader. The old whiptail script did sgdisk/mkfs/mount/grub; the new one does not. No roadmap item (gaming, DEs, greeter) matters until an install boots, so the disk+boot layer is the unambiguous depth-first next step: it deepens the existing executor rather than adding a new surface.
- **Depth note:** This adds zero new user-facing features; it completes the existing install pipeline so 'installs & boots' becomes true. It reuses the established pattern (pure planner + existing Step types + thin subprocess wrapper) and the existing dry-run/test infrastructure. UI screens for disk selection come in a later cycle — this task keeps the layer pure and testable, wiring only a --disk/--firmware CLI path for dry-run verification.

## Contracts
MUST NOT break any of the 186 existing tests. executor.py keeps `Step = RunCommand | WriteTargetFile` and the existing `compile_steps(plan, *, target='/mnt', init_id)` signature — extend it ONLY with new optional keyword args `disk_plan=None` (a DiskPlan or None) so all existing call sites/tests pass unchanged. When disk_plan is provided, disk-preparation steps come FIRST (before pacstrap) and bootloader steps come LAST (after service enabling). New module disks.py: `parse_lsblk(json_text: str) -> list[BlockDevice]` (pure; BlockDevice dataclass with at least name, path, size_bytes, model, is_removable, has_mounted_partitions); `plan_disk(device: BlockDevice, firmware: str) -> DiskPlan` where firmware is 'uefi' or 'bios' (raise DiskError on anything else, on device too small < 8 GiB, or on has_mounted_partitions=True); `discover() -> list[BlockDevice]` is the ONLY function allowed to call subprocess (runs `lsblk --json -b -o NAME,PATH,SIZE,TYPE,MODEL,RM,MOUNTPOINTS`), never called at import time. DiskPlan is a frozen dataclass carrying device path, firmware, and the ordered partition spec. All pure functions raise DiskError (new exception in disks.py), never SystemExit. Python 3 stdlib only. Every file ≤ 500 lines. Follow existing code style (dataclasses, type hints, module docstrings) as in executor.py/plan.py.

## Brief
Repo: /home/gentoobdw/wheatley-linux, package at packages/wheatley-installer/. Read executor.py, plan.py, __main__.py, and one test file first to absorb conventions. Then:

1) NEW `wheatley_installer/disks.py`:
   - `class DiskError(Exception)`.
   - `@dataclass(frozen=True) BlockDevice`: name, path, size_bytes:int, model:str, is_removable:bool, has_mounted_partitions:bool.
   - `parse_lsblk(json_text)`: parse `lsblk --json -b` output; keep only type=='disk' entries; a disk has_mounted_partitions if it or any child has a non-empty mountpoint (treat '[SWAP]' as mounted); malformed JSON or missing keys → DiskError.
   - `plan_disk(device, firmware)`: returns frozen DiskPlan. UEFI layout: GPT, p1 = 512MiB EFI System (vfat, mounted at /boot/efi), p2 = rest ext4 → /. BIOS layout: GPT, p1 = 1MiB BIOS-boot partition (ef02, no fs), p2 = rest ext4 → /. Validate: firmware in {'uefi','bios'} else DiskError; size_bytes >= 8 GiB else DiskError; has_mounted_partitions → DiskError (refuse to nuke the running system/live USB).
   - `discover()`: thin subprocess wrapper around lsblk (check=True, capture stdout, feed parse_lsblk). No subprocess import used anywhere else in the module's pure paths; no calls at import time.
   - Partition device naming: append '1'/'2' to the disk path, inserting 'p' when the path ends in a digit (nvme0n1 → nvme0n1p1; sda → sda1). Unit-test this rule explicitly.

APPEND after all existing steps: chrooted `grub-install` (UEFI: `--target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=Wheatley`; BIOS: `--target=i386-pc <disk>`) and chrooted `grub-mkconfig -o /boot/grub/grub.cfg`, using the same chroot invocation style the file already uses for service enabling. Keep file ≤500 lines; if it would exceed, move the disk-step helpers into disks.py (e.g. `disk_steps(plan)`/`bootloader_steps(plan, target)` returning Step lists) and import them — preferred layout.
